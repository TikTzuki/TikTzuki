# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

Personal knowledge hub and documentation site for TikTzuki (Software Architect / Backend Engineer). Contains a
Docusaurus-powered documentation/blog site and a GitHub profile auto-updater.

## Project Layout

- `tik_space/` — Docusaurus 3.10.2 documentation site (TypeScript, React 19, SCSS)
- `update_profile/` — Node.js script that fetches daily quotes from ZenQuotes API and updates README.md
- `.github/workflows/` — CI/CD: `release_docs.yml` deploys docs, `release_profile.yml` runs daily quote updater

## Build & Development Commands

All commands run from `tik_space/`:

```bash
cd tik_space
pnpm install          # Install dependencies
pnpm sync             # Pull in docs owned by tiktuzki-gitops / senior-architect
pnpm start            # Dev server with hot reload (runs sync first)
pnpm build            # Production build (runs sync first)
pnpm serve            # Serve production build locally
pnpm typecheck        # TypeScript type checking (tsc)
pnpm clear            # Clear Docusaurus cache
```

Node.js >= 20 required. CI uses Node 22 + pnpm.

## Documentation Site Architecture

**Docusaurus config:** `tik_space/docusaurus.config.ts`

- Sidebars auto-generated from filesystem (`sidebars.ts` uses `autogenerated` directive)
- Dark mode by default
- i18n: English (default) + Vietnamese (`i18n/vi/`)
- Math: remark-math + rehype-katex
- Diagrams: Mermaid (via `@docusaurus/theme-mermaid`)
- Styling: SCSS via `docusaurus-plugin-sass`, custom styles in `src/css/custom.scss`
- Future v4 compatibility flag enabled

**Content structure:**

- `tik_space/docs/` — Docs filed by **genre**, not topic: `how-it-works/`, `production-patterns/` (synced),
  `system-design/`, `operations/` (synced), `interview-prep/`, `reference/`, `archive/`. Subject lives in tags. See
  `../TAXONOMY.md`.
- `tik_space/scripts/sync-knowledge.mjs` — copies in docs owned by sibling repos before every build
- `tik_space/docs/tags.yml` — the controlled tag vocabulary; an undefined tag fails the build
- `tik_space/sidebarItemsGenerator.ts` — regroups the flat 41-lesson category into its seven sets
- `tik_space/redirects.json` — every URL the 2026 restructure moved
- `tik_space/blog/` — Blog posts with `authors.yml`
- `tik_space/src/components/` — React components (HomepageFeatures, PageTree, ui primitives)
- `tik_space/src/pages/` — Standalone pages including interactive demos (e.g., elliptic curve visualization)

## Synced Documentation — do not edit in place

This site publishes docs it does not own. Before each build, `tik_space/scripts/sync-knowledge.mjs` copies:

| Source of truth                                                                     | Rendered at                       |
|-------------------------------------------------------------------------------------|-----------------------------------|
| `tiktuzki-gitops/docs/operations/`                                                  | `/docs/operations`                |
| files listed in `tiktuzki-gitops/knowledge-map.yaml`                                | routed under `/docs/operations/…` |
| `senior-architect/plugins/production-patterns/skills/production-review/references/` | `/docs/production-patterns`       |

The 41 lessons carry **no front matter of their own** — the sync injects title/tags/position
from `senior-architect/knowledge-map.yaml` into its copy. Never add front matter to the
source files: `production-review/SKILL.md` links all 41 by relative path and the plugin
resolves them through `${CLAUDE_PLUGIN_ROOT}`.

Both destination directories are **gitignored** and wiped on every build, so an edit made here is
lost. Each one contains a `.synced-from` file naming the repo to edit instead. The script uses a
sibling checkout (`../../<repo>`) when present so unpushed edits preview locally, and shallow-clones
from GitHub otherwise.

Because those repos change without a push here, the deploy workflow also runs nightly and accepts
`repository_dispatch` with `event_type: knowledge-updated`.

Sidebars are autogenerated from the filesystem, so a new file in a source repo needs no change here.

## Build strictness

These are all set to fail the build rather than warn, so a restructure cannot silently rot:

| Setting                                         | Catches                                    |
|-------------------------------------------------|--------------------------------------------|
| `onBrokenLinks: 'throw'`                        | dead internal links                        |
| `onBrokenAnchors: 'throw'`                      | dead `#anchor` targets                     |
| `markdown.hooks.onBrokenMarkdownLinks: 'throw'` | relative `.md` links to moved files        |
| `markdown.hooks.onBrokenMarkdownImages`         | broken markdown images (throws by default) |
| `docs.onInlineTags: 'throw'`                    | a tag not defined in `docs/tags.yml`       |

Not covered: JSX `<img src>` (only mdast image nodes are visited) and orphaned assets
nothing references. Check those with the loops in `../TAXONOMY.md`.

Published markdown is processed as MDX, so void tags must be self-closed (`<br />`).

## Deployment

Docs deploy to `tiktzuki.github.io` via `peaceiris/actions-gh-pages` on push to `master`. The build output from
`tik_space/build` is pushed to the `gh-pages` branch of the external repo `TikTzuki/tiktzuki.github.io`.

## Conventions

- Documentation is written in Markdown/MDX with KaTeX for math notation and Mermaid for diagrams
- Component styling uses SCSS modules (`.module.scss` pattern)
- No test framework or linter configured — `typecheck` is the main code quality check
- Known bugs, deferred decisions and fragile couplings are recorded in [TECH_DEBT.md](TECH_DEBT.md).
  Check it before debugging something odd, and add to it rather than leaving a finding in a chat log.
- `pnpm build` alone can emit a stale CSS bundle; use `pnpm clear && pnpm build` when verifying a
  theme or style change (see TECH_DEBT.md §2.1)
